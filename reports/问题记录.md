## 代表错误的原因复核

在原数据库上分别执行标准 SQL、原预测和修改后的预测。每例只改一个子句、表达式或字面值，其余 SQL 保持原样。用批测的同一比较函数复核，七处修改均使结果与标准一致。表中解释直接导致执行差异的条件。[完整 SQL 和数据库检查结果](../results/sql-diagnostics.json)

| 样本 | 单点修改与执行证据 | 原因判断与后续改进方向 |
| --- | --- | --- |
| `DB_schema_synonym-02040-post` | 增加 `EXISTS`，要求候选国家至少有一条语言记录。结果从 179 行变为标准的 173 行。独立检查发现恰有 6 个国家没有语言记录。 | 丢分来自候选集合定义。题意可以理解为全国集合，也可以理解为有语言记录的集合。生成前应明确“没有英语记录”和“有其它语言记录”的区别。 |
| `DB_schema_abbreviation-01515-post` | 将 `'Yes'` 改成 `'yes'`，从 0 行变为标准的 1 行。实际 `hd` 值只有 `no`（14 行）和 `yes`（1 行）。 | 等值过滤的文本大小写导致空结果。枚举条件可先从数据库找合法取值，再生成 SQL。 |
| `NLQ_keyword_synonym-00147-post` | 去掉 `CAST(Horsepower AS INTEGER)`，计数从 49 恢复为标准的 281。额外计入的 232 行都以文本存储，例如文本 `'90'` 在 SQLite 的文本比较中大于 `'150'`。 | 标准 SQL 依赖 `TEXT` 比较，模型显式做数值比较。数值比较符合“马力超过 150”的通常含义。这一条评测失分应归为存储类型与标准查询语义的分歧。 |
| `NLQ_column_synonym-00019-post` | 将输出的 `cm.FullName` 改为 `cm.Maker`。两次均返回 11 行，修改后返回值与标准一致。 | 同一厂商可对应简称与全名。问题改写改变了模型选择的列。核对目标列时需要区分实体身份与要求输出的表示。 |
| `NLQ_column_synonym-00378-post` | 将 `Name = 'United States'` 改为 `GovernmentForm = 'US Territory'`。聚合对象从美国本身变为 3 个领土，结果由 `(8510700.0, 278357000)` 变为标准的 `(510.3333333333333, 329000)`。 | 模型把关系条件落到国家名称。它仍使用了标准的 `GNP` 列，因此这次执行差异能定位到 `WHERE`。改写中 GDP 与原题 GNP 的差异也应在标注审查中记录。 |
| `SQL_sort_order-00171-pre` | 去掉次排序键 `grade`，结果从 9 变为标准的 12。9 至 12 年级各有 4 人，全部并列。 | 两条 SQL 都能选中一个人数最多的年级。当前库中标准 SQL 恰好返回 12。评测时应明确并列选取规则，或者在诊断中标记允许多解的样本。 |
| `NLQ_keyword_synonym-00281-pre` | 将预测中的 `'Jetblue Airways'` 改为 `'JetBlue Airways'`，计数从 0 变为标准的 100。实际航司表存在后者。 | 字面值大小写影响匹配。下方输入对照进一步核对了问句拼写与 SQL 字面值的关系。 |

上述单点复核检验的是这些 SQL 在同一数据库上的执行差异。对每类扰动的总体影响仍应使用该类所有抽样配对统计。对业务题意可能允许不同答案的样本，保留原始 EX，并在案例中记录标准查询的假设。
