# 任务1 · Dr.Spider 基线实验报告

## 数据与实验设置

本实验使用 Dr.Spider 的扰动前（pre）和扰动后（post）配对问句，以自然语言问题和 SQLite 表结构作为模型输入。固定版本的数据包含 17 类扰动和 15,269 个配对实例，基于 Spider-dev 的 1,034 道原题。同一道原题可能出现在多个扰动类别中。两批实验覆盖其中五类。[数据来源](../manifests/data_source.json) · [数据盘点](../manifests/data_inventory.json) · [五类配对案例](问题记录.md#五类配对案例)

| 项目 | 实际设置 |
| --- | --- |
| 实验批次与日期 | 2026-11-18（北京时间）。`sol-25pairs` 每类 5 对，`sol-50pairs-seed43` 每类 10 对。 |
| 模型 | Thingo API。全部 150 条预测的请求与响应模型 ID 均为 `gpt-6-sol`。digest 和 `system_fingerprint` 均未提供。 |
| 抽样方法 | 各类别内无放回抽样。25 对批次使用种子 42，50 对批次使用种子 43。同一类别和下标同时取 pre、post。 |
| 提示词与请求参数 | 系统提示要求根据问题和表结构生成一条 SQLite SELECT 查询，只输出 SQL，保留必要的值。用户消息为完整建表语句和问题。显式设置 `stream=false`，其余生成参数采用供应商默认值。 |
| 代码与依赖 | 运行时 HEAD 为 `c972bac074c06419187a3e77432118b242bd3362`，工作区有未提交改动。两批的三份源码哈希和依赖清单一致。API 脚本的 Git 文件与实验原件字节一致。`src/baseline.py` 在实验工作区使用 CRLF，在 Git 中保存为 LF，统一行尾后内容一致。 |
| 评测实现 | 比较函数来自上游提交 `e97acc546ecbee8fa27fa8dbf025ef61493a876c`。在每题对应的单个 SQLite 库上执行预测与标准 SQL，比较结果是否一致。 |
| 数据库及 SQL | DB 类 post 使用扰动后的数据库。保留实际值与 `DISTINCT`，按标准 SQL 是否含 `ORDER BY` 决定比较时是否考虑行序。 |
| 结果证据 | 两批文件均包含配置、依赖、样本标识、原题号、数据库哈希、预测 SQL 和逐题评分，以及原始请求与响应的 SHA-256。[25 对首批](../results/baseline/sol-25pairs.json) · [50 对主批](../results/baseline/sol-50pairs-seed43.json) |

## 实际错误分布

分母为主批的 31 个执行结果不一致侧。每侧按预测和标准 SQL 的主要差异计入一个类别。部分样本存在多处差异。首批的 6 条不一致单独列出。[逐题标签与诊断记录](问题记录.md#执行结果不一致样本)

## 结果与局限

- 50 对主批中，问题列名同义表达的 post 得分最低（3/10），比该类 pre 低 30 个百分点。排序类在首批下降 20 个百分点，在主批上升 10 个百分点。
- 主批 31 条不一致中，最常见的是关联或候选集合差异，占 11/31。两批共选七处差异做单点修改，修改后均通过同库执行比较，覆盖候选集合、文本字面值、类型转换、输出列、筛选条件和并列规则。[逐例诊断](问题记录.md#代表错误的原因复核)
- JetBlue 对照中，原问句复测再次生成 `Jetblue Airways`，计数为 0。只改问句中名称的大小写后，预测计数为 100，与标准一致。每种条件新增一次请求，证据限于该题。[对照记录](../results/diagnostics/jetblue-model-control.json)
- EX 反映所抽配对在指定单库上的结果一致性。案例中观察到标准 SQL 对并列选取、文本比较和关联范围的处理会影响评分。[代表错误的原因复核](问题记录.md#代表错误的原因复核)
