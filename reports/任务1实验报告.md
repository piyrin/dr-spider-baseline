### 12 类典型配对案例

每类从 850 对主批中选一对前通过、后未通过的样本，优先展示同类中重复出现的前后变化。各类占比的分母为该类在主批中的标注数，同一道原题可能对应多个扰动对。案例对照输入的变化、参考 SQL 要求调整或保留的部分，以及模型实际生成的差异。题意允许多种解释的地方，结论限于本次单库 EX 的判分差异。[主批逐对复核](../results/drspider-17x50/prepass-postfail-review.csv) · [前后题面、SQL 与评分](../results/drspider-17x50/predictions.csv)

1. **返回内容多选**（`NLQ_column_carrier-00499`）。问句从「十年级学生的姓名是什么」改为「哪些学生在读十年级」，把明确的姓名要求变成了对学生的指代。参考 SQL 两侧都只返回 `name`。模型 pre 只返回姓名，post 保留了 `WHERE grade = 10`，却额外返回了 `ID` 和 `grade`。在主批标注为本类的 27 对中，至少 13 对（10 道原题）同时出现了姓名或名称要求省略、post 多返回其他列的现象。
2. **筛选值和库内存法对不上**（`NLQ_value_synonym-00154`）。问句把 `USA` 改称 `United States`，库内 `Country` 仍存 `'USA'`。模型 pre 用 `'USA'` 查到 12 家航司，post 照用新写法，结果变为空。只把筛选值换回 `'USA'` 就恢复了 12 行。26 对中有 9 对来自同一筛选值换说法，是该类最多的扰动组。
3. **去重口径不同**（`SQL_NonDB_number-00054`）。题目从年龄最小的 3 名获胜者改为 5 名，参考 SQL 两侧都对「姓名、排名」去重后取前 N 项。模型两侧均按比赛记录直接取前 N 项。pre 的前 3 项恰好都不同，post 的前 5 项中有一组「姓名、排名」重复，占掉了一个名额。6 对中有 3 对（2 道原题）出现这一现象，补上 `DISTINCT` 后这 3 对的 post 结果都与参考一致。
4. **题意和表、列没对上**（`DB_schema_synonym-01010`）。问句仍然要查 Robbin CV 这份文档的描述，描述列由 `Documents.Document_Description` 改名为 `Documents.detailing`。模型 pre 从文档表取描述，post 额外连接 `Templates`，取成模板的 `Template_Details`。5 对中有 3 对（2 道原题）来自库字段同义替换，其中同一文档题的两次改名都出现了这种跨表误取。
5. **筛选范围变了或漏掉限制**（`DB_schema_abbreviation-01621`）。国家、频道和编剧相关字段缩写后，参考 SQL 仍以国家为单位检查该国有无频道播出 Todd Casey 的作品。模型 pre 检查同一国家的所有频道，post 只检查当前频道，多纳入了两个仍有相关频道的国家。该类 5 对中有 2 对是在库字段缩写后出现比较范围变化。
6. **分组粒度不同**（`NLQ_value_synonym-00427`）。问句把「数一数九年级或十年级的学生」改为「确定九年级和十年级的学生人数」，参考 SQL 两侧都求一个合计。模型 pre 返回总数 8，post 按年级分成两行，各返回 4 人。4 对中有 2 对从总计变为分组，另外 2 对源于同一道网球题，从按赛事名称汇总变为按赛事 ID 细分。
7. **缺失记录被当成 0**（`SQL_comparison-00098`）。题目的死亡人数条件从大于 10 改为小于 10，参考 SQL 两侧都只统计有死亡记录的战斗。模型 post 正确反转了比较符，同时改用 `LEFT JOIN` 和 `COALESCE`，把 3 场缺少死亡记录的战斗按 0 人纳入。4 对中有 3 对（2 道原题）在比较条件改成小于或至多某个门槛后纳入了原来排除的缺失项。题面未规定如何处理缺失记录。
8. **自行拼接字段**（`DB_DBcontent_equivalence-00125`）。访客姓名从 `Name` 拆为 `first_name` 和 `last_name`，参考 SQL 改为分别返回两列。模型 pre 返回一列 `Fernando Gago` 并通过，post 将两个姓名字段拼成一列，与参考的两列输出不同。3 对中有 2 对在字段被拆分后将分量重新合成一列，另一个拆分案例涉及成绩单日期。
9. **并列时取法不同**（`SQL_NonDB_number-00103`）。题目把人口最少的 3 个改成 5 个，模型正确将 `LIMIT 3` 改为 `LIMIT 5`，同时加了按名称升序的次排序键。此次执行返回了相同的 5 个地名，但人口为 0 的并列项顺序不同，题面也没有规定并列顺序。主批 3 对（2 道原题）都出现了扩大条数后按名称处理人口并列项的情况。
10. **拆分后漏选字段**（`DB_DBcontent_equivalence-00347`）。到达时间从 `date_arrived` 一列拆为日期 `date_arrived` 和时间 `time_arrived`，离开时间保持原样。模型 pre 与参考都返回两列，post 沿用原投影，漏掉了参考新增的 `time_arrived`。主批 2 对都在日期时间拆分后漏选了时间字段。
11. **先连接再计数，缩小了统计范围**（`NLQ_value_synonym-00142`，主批仅 1 对）。题面把数字写成 `two`、`three`，并改写了厂商的称呼，车型数和车辆数仍应各按自己的记录统计。模型 pre 分开计数，post 在同一连接结果上算两项，丰田原有 2 个车型，连接后只剩 1 个进入计数，因此被排除。
12. **字段含义变了，排序方向没跟着变**（`DB_DBcontent_equivalence-00304`，主批仅 1 对）。题目仍要求按乐团成立年份降序，数据库把成立年份换为存续年数。成立越晚，存续年数越短，参考 SQL 因此改用 `ORDER BY year_of_existence ASC`。模型 post 换对了字段，却沿用了 `DESC`。

## 扩样与修复验证

同一纯表结构基线共扩样 **344 对**，包括 130 对留出和 26、44、83、61 对四轮定向补测，各批按原题 ID 隔离。最近两轮优先筛第 3–10 类，共 **144 对、288 次生成**。10 对前对后错中，4 对需要人工判断，4 对是参考 SQL 问题，另外 2 对确认为库值错误和返回多选。全部扩样共 45 对前对后错，10 对明确入类，19 对复现差异但题意待定。其中 18 对能对应上表，另 1 对是题面未指定排序方向。[留出与定向扩样](../results/drspider-17x50/expansion/README.md)

验证节点效果时，每类同时报告实际修复数与分母，并在原本通过的对上检查回退。测试样本按原题去重，与用于设计节点的原题隔离。只读 SQL 单点修改用于定位成因，Agent 的收益以实际生成后复评为准。

## 早期试跑 · 数据与实验设置

本实验使用 Dr.Spider 的扰动前（pre）和扰动后（post）配对问句，以自然语言问题和 SQLite 表结构作为模型输入。固定版本的数据包含 17 类扰动和 15,269 个配对实例，基于 Spider-dev 的 1,034 道原题。同一道原题可能出现在多个扰动类别中。两批实验覆盖其中五类。[数据来源](../manifests/data_source.json) · [数据盘点](../manifests/data_inventory.json) · [五类配对案例](问题记录.md#五类配对案例)

| 项目 | 设置 |
| --- | --- |
| 运行日期 | 2026 年 11 月 18 日（北京时间） |
| 模型与参数 | Thingo API 的 `gpt-6-sol`。关闭流式响应，其余参数沿用服务端默认值。服务端未提供模型 digest 或 `system_fingerprint`。 |
| 配对抽样 | 五类扰动分别无放回抽样。首批每类 5 对（种子 42），主批每类 10 对（种子 43）。每对选取同一下标的 pre 和 post。 |

## 早期试跑小结

50 对主批的 EX 从 **72%（36/50）降至 66%（33/50）**。问题列名同义表达下降最多，从 60% 降至 30%。排序类在首批下降 20 个百分点，在主批上升 10 个百分点，两批样本的变化方向不同。

主批最常见的差异是关联或候选集合，占 31 条不一致中的 11 条。七条代表预测各修改一处 SQL 后均与标准结果一致。JetBlue 对照中，原问句复测返回 0，只调整问句中航司名的大小写后返回 100，与标准一致。[SQL 诊断](问题记录.md#代表错误的原因复核) · [JetBlue 对照](../results/diagnostics/jetblue-model-control.json)

结论限于抽取的样本和对应的单个 SQLite 库。并列选取、文本比较和关联范围会影响执行评分。JetBlue 对照每种问句各新增一次请求。
