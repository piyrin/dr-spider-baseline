# Dr.Spider 问题子类与开发样本

按复核结果纳入 **97 对、79 道原题**，其中主批 87 对、扩样 10 对。按题面或数据库的变化以及实际 SQL 差异，归为 **26 个子类**。子类用于标注共同的错误机制。已选十题的编排方法与运行结果另见验收材料。[十题验收](../../results/task2/submission/acceptance/README.md)

原报告的 12 类用于描述主要错误。这里每对样本只归入一个主要子类，便于取样。某一官方扰动可以出现在多个子类，同一子类也可以跨官方扰动。样本编号的前半段是官方扰动名。表中的原题数在各子类内去重，同一道原题的不同变体可能落入多个子类。

## 原标签和实际 SQL 的差异

- `NLQ_column_synonym-00546` 原标为返回内容多选，post 实际只返回 `Name`。将筛选值 `'French'` 换为库值 `'France'` 后，执行结果与参考一致，因此归入「同一对象用另一名称表达」。
- `NLQ_column_carrier-00381` 原标为筛选范围变化，pre 和 post 的筛选条件相同，post 少了 `DISTINCT`，因此归入「明细行去重口径变化」。
- `SQL_DB_text-00048` 原标为筛选值与库值不匹配，post 字面值仍为 `'Honda'`。只将它匹配的厂商列由 `Maker` 换回 `FullName`，执行结果即与参考一致，因此和 `SQL_comparison-00044` 归入同一个表列子类。
- `NLQ_column_synonym-00198` 和 `NLQ_column_synonym-00200` 同时出现返回整行和筛选值大小写变化。只改筛选值后能返回记录，列仍多于参考。两对归入输出线索变宽，单节点实验时可同时记录列和筛选值是否各自匹配。
